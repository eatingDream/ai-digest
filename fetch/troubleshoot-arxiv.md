# Handling a missing arXiv batch (read this file only when the `Note:` lines of report.md / the fetch output contain "⚠️ weekday batch")

- **Handling a missing arXiv batch**: when `P` is a weekday the batch is long online, so a gap is a **real recall failure** (or arXiv took the day off, e.g. there was no list on Thursday 11/12), not "no papers today".
  - If the notes in `report.md` contain "⚠️ weekday batch … is missing from both /pastweek and /new" (fetch already retried once internally): **before reading the paper triage** run `python3 fetch/fetch.py --daily --only arxiv,hf_daily` once more (about 20 s; the output goes to `runs/P/fetch-extra/` and **does not overwrite `fetch/`** — read that `triage-papers.md` for papers; the extra run re-fetches the same full HF board for the window without advancing `hf_daily:last`, so HF papers are in there too). If it is still missing, use WebFetch to look at the titles/dates on `https://arxiv.org/list/cs.LG/new` and `https://arxiv.org/list/cs.LG/pastweek` to tell an arXiv holiday/delay from a fetch failure; if it is a holiday treat the papers section as empty and write one line with the reason in the "Source status" section of `filter-log.md`. **Do not poll and do not wait**; there is no "13:00 catch-up" job and no catch-up mode.
  - If it still cannot be fetched after confirming a real failure: publish as usual (papers section missing), say so in `filter-log.md`; the **next** day's run will not backfill this batch automatically (`--catchup` is off by default). This is the only process remark allowed in the push message: add a line after the summary "Note: the arXiv batch for P (M/D) could not be fetched; the papers section is missing", and do not stop to wait afterwards.
  - A daily whose papers section is empty while `P` is a weekday is almost surely a recall failure.
